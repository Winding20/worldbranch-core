# 世界包规范

> 这份文档是**合同**。照着它写数据，就能给 WorldBranch 增加一段新的历史，
> 不需要改引擎代码。人和 AI 都按这份文档办事。

---

## 0. 一句话说清

一个"世界包" = 一段历史的数据描述。引擎只负责解释这些数据：
推进时间、判定史实条件、抛出决策、结算后果、最后按 rubric 打分。

**引擎不认识任何具体地名、人名、派系名。** 凡是"长安""河北""安禄山"
这样的词，只能出现在世界包里。

---

## 1. 目录结构

```
backend/app/seed/packs/<world_key>/
├─ world.json        必需。元信息：标题、时段、角色、期限
├─ rubric.json       必需。结局评分：指标、权重、评级
├─ decisions.json    可选。决策规则（v2 起支持，见第 5 节）
└─ notes.md          可选。给作者自己的笔记，引擎不读
```

`<world_key>` 用小写字母、数字和下划线，例如 `tang_755`、`sanguo_208`。
**目录名必须与 `world.json` 里的 `key` 完全一致**，否则加载时报错。

## 2. `world.json`

```json
{
  "key": "tang_755",
  "title": "安史之乱",
  "subtitle": "天宝十四载 · 广德元年",
  "start_date": "0755-11-01",
  "horizon_months": 96,
  "role": "唐廷",
  "role_brief": "你是唐廷。天下兵马、府库钱粮、藩镇顺逆，都由你决断。",
  "theme": "crimson-theater",
  "seed_module": "app.seed.anlushan_755",
  "labels": {
    "advance_unit": "月",
    "horizon_label": "广德元年"
  }
}
```

| 字段 | 必需 | 说明 |
|---|---|---|
| `key` | ✅ | 世界标识，必须与目录名一致 |
| `title` | ✅ | 标题，显示在界面上 |
| `start_date` | ✅ | 开局日期，`YYYY-MM-DD`。注意年份是四位：755 写作 `0755` |
| `horizon_months` | ✅ | 从开局算多少个月后期末评估，必须与 `rubric.horizon_months` 一致 |
| `role` | ✅ | 玩家扮演谁，例如"唐廷""蜀汉""魏廷" |
| `subtitle` | | 副标题，显示在标题下方 |
| `role_brief` | | 一句话说明玩家处境 |
| `theme` | | 界面配色主题：`crimson-theater`（近黑绯红）/ `celadon-paper`（青瓷白） |
| `seed_module` | | 内容播种模块的 Python 路径。**v1 的地区/派系/人物/军队/史实仍由它提供**，见第 6 节 |
| `labels` | | 界面文案：`advance_unit`（推进单位）、`horizon_label`（期限的名称） |

## 3. `rubric.json`

结局评分。到期末时按指标算出 0–100 分，按评级门槛给一个名字和一句评语。

```json
{
  "horizon_months": 96,
  "grades": [
    [85, "中兴", "两京无恙，河北未失，天下犹可为。"],
    [60, "克复", "叛乱虽平，然师老兵疲、府库空虚。"],
    [0,  "崩坏", "乱事未平，藩镇自立。"]
  ],
  "metrics": [
    {
      "key": "capitals",
      "label": "两京",
      "weight": 0.2,
      "kind": "regions_held",
      "regions": ["changan", "luoyang"],
      "faction": "tang"
    }
  ],
  "facts": {
    "capitals_held": {
      "kind": "count_regions_held",
      "regions": ["changan", "luoyang"],
      "faction": "tang"
    }
  }
}
```

### 3.1 硬性规则

- `grades` 按门槛**从高到低**排列，最后一项的门槛应当是 `0`；
- `metrics` 的 `weight` 之和必须等于 **1.0**（校验器会算）；
- `metrics[].label` 不能重复（它就是输出里的字段名）；
- `horizon_months` 必须与 `world.json` 一致。

### 3.2 指标类型（`kind`）

| kind | 含义 | 需要的字段 |
|---|---|---|
| `regions_held` | 指定地区里有几个在目标派系手中 | `regions`, `faction` |
| `rebellion_status` | 叛乱状态：全平 / 首领已死 / 仍在 | `faction`，可选 `leader`、`scores` |
| `faction_treasury` | 派系府库折算成 0–100 | `faction`，可选 `offset`、`span` |
| `faction_field` | 派系某个 0–1 字段（如 `legitimacy`） | `faction`, `field` |
| `max_unrest` | 全境最高民变，越高越差 | 可选 `span`、`invert` |
| `region_control` | 地区实际控制权：直辖 / 名义自专 / 沦陷 | `regions`, `faction`, `scores` |

`rebellion_status` 的 `scores` 默认 `{"over":100,"leader_gone":60,"ongoing":20}`；
`region_control` 的 `scores` 默认 `{"held":100,"autonomous":40,"lost":0}`。

### 3.3 事实清单（`facts`）

算完分顺便记录几条"发生了什么"，供界面和 AI 分析引用。可用 kind：

| kind | 输出 |
|---|---|
| `count_regions_held` | 数字 |
| `no_hostile_regions` | 布尔 |
| `list_hostile_regions` | 地区名数组 |
| `list_autonomous_regions` | 地区名数组 |
| `character_alive` | 布尔 |

---

## 4. 地区、派系、人物、军队的 key

`rubric.json` 和 `decisions.json` 里引用的 key，必须在世界内容里真实存在。
校验器会去数据库里核对，拼错会直接报出来——这是最常见的错误来源
（例如把 `hebei_plain` 写成 `hebei`）。

v1 的内容仍由 `world.json` 的 `seed_module` 提供，key 定义在那个模块的
`REGIONS` / `FACTIONS` / `CHARACTERS` / `ARMIES` 里。

---

## 5. `decisions.json`（决策规则）

每条规则 = 什么时候问（`when`）+ 问什么（`title`/`description`/`options`）+ 选了会怎样（`effects`）。
引擎只认识下面两张词表里的原语。

```json
{
  "rules": [
    {
      "kind": "famine_relief",
      "cooldown_months": 6,
      "when": { "unrest_above": 0.55 },
      "focus": { "region": "worst_unrest" },
      "title": "{region}请求赈济",
      "description": "……",
      "options": [
        {
          "key": "relieve",
          "label": "开仓赈济",
          "note": "府库 −90 万贯，民变下降",
          "effects": {
            "treasury": -900000,
            "unrest": { "region": "focus", "delta": -0.22 }
          }
        }
      ]
    }
  ]
}
```

### 5.1 条件词表（`when`，须全部满足）

| 条件 | 参数 | 含义 |
|---|---|---|
| `treasury_below` | 数字，或 `{faction, amount}` | 府库低于阈值 |
| `unrest_above` | 0–1 | 任一地区民变高于阈值 |
| `legitimacy_below` | 0–1 | 任一派系威望低于阈值 |
| `region_held_by` | `{region, faction}` | 某地在某派系手中 |
| `faction_has_region` | `{faction}` | 该派系至少占一地 |
| `character_alive` | `{character}` | 某人还在世 |
| `character_loyalty_below` | `{character, value}` | 某人忠诚低于阈值 |
| `chance` | 0–1 | 按随机数命中 |

### 5.2 效果词表（`effects`）

| 效果 | 参数 | 含义 |
|---|---|---|
| `treasury` | 增量 | 玩家派系府库 |
| `legitimacy` | 增量 | 玩家派系威望 |
| `unrest` | `{地区: 增量}`，或 `{target:"focus", delta}` | 民变 |
| `grain` | 同上 | 存粮 |
| `relation` | `{派系: 增量}` | 与该派系的关系 |
| `autonomy` | `{地区: true/false}` | 是否藩镇自专 |
| `control` | `{地区: 派系}` | 地区易手 |
| `loyalty` | `{人物: 增量}` 或 `{character, delta}` | 忠诚 |
| `troops` | `{军队: 增量}` 或 `{army, delta}` | 兵员 |
| `morale` | `{军队: 增量}` | 士气 |

### 5.3 文案占位

`title` / `description` / `label` / `note` 里可用：

- `{region}` —— 本次聚光的地区名（由 `focus` 决定）
- `{month}` —— 当前推进月数

### 5.4 `focus`（把镜头对准哪）

- `{"region": "jiangxia"}`：固定地区
- `{"strategy": "worst_unrest"}`：民变最重的那块
- `{"strategy": "first_region"}`：第一块地区

未知的条件/效果/策略会在**加载时**报错，不会等到某个月才炸。

## 5.5 `content.json`（内容数据）

给了这个文件，世界就不需要 Python 播种器——地区、派系、人物、军队、史实全在数据里。
`backend/app/seed/packs/sanguo_208/` 就是完整例子。

```json
{
  "world": { "name": "赤壁", "era": "建安十三年（208）", "start_date": "0208-07-01",
             "description": "…", "provenance": "…", "scenario": { … } },

  "regions": [ { "key": "jiangxia", "name": "江夏", "lat": 30.55, "lon": 114.3,
                 "population": 400000, "faction_key": "liu", "geo": null } ],

  "factions": [ { "key": "liu", "name": "刘备", "kind": "state",
                  "capital_region_key": "jiangxia",
                  "treasury": 60000, "legitimacy": 0.62, "military": 18000 } ],

  "relations": [ { "from_key": "cao", "to_key": "liu", "kind": "hostility", "value": -0.9 } ],

  "trade_pairs": [ ["jiangxia", "chaisang", 1200] ],

  "characters": [ { "key": "liu_bei", "name": "刘备", "role": "lord",
                    "faction_key": "liu", "ability": 0.74, "loyalty": 1.0,
                    "ambition": 0.55, "location_region_key": "jiangxia",
                    "office": "左将军", "office_rank": 3, "office_kind": "military" } ],

  "armies": [ { "key": "liu_army", "name": "刘备军", "faction_key": "liu",
                "commander_key": "liu_bei", "region_key": "jiangxia",
                "troops": 18000, "morale": 0.55, "supply": 0.45 } ],

  "events": [ { "key": "alliance_formed", "date": "0208-10-15", "title": "孙刘结盟",
                "category": "diplomacy", "description": "…",
                "conditions": { "character_alive": "sun_quan" },
                "effects": {}, "divergence_note": "…", "source": "《三国志》" } ]
}
```

要点：

- `start_date` 与 `events[].date` 都要写成 **四位年份**，例如 `0208-07-01`；
- `farmland` / `grain_stock` 不必填，按人口自动推算；
- `geo` 可以为 `null`：没有边界时界面用经纬度画点，不会白屏；
- 仲裁者会校验 `faction_key` / `character_key` / `region_key` 的引用是否都存在。

**内容来源二选一**：给了 `content.json` 就全用数据；否则回退到 `world.json` 的
`seed_module`（唐史切片就是这种老方式）。

## 5.6 玩家派系

`world.json` 里必须写清楚：

```json
"player_faction": "liu",
"hostile_faction": "cao"
```

引擎判定「地区在谁手里」「失守后改归谁」全靠这两个 key。以前它们写死在
`engine/history.py` 里（tang / yan），现已参数化。

## 6. 当前边界（重要）

| 内容 | 现在在哪 |
|---|---|
| 标题、时段、角色、期限 | ✅ `world.json` |
| 结局评分 | ✅ `rubric.json` |
| 决策规则 | ✅ `decisions.json`（新世界一律走这条） |
| 地区/派系/人物/军队/史实 | ✅ `content.json`（新世界）／⏳ 唐史仍是 Python 播种器 |
| 界面文案 | ✅ `world.json` 的 `labels` + `role_brief` |

**剩下的不彻底之处**：唐史（`tang_755`）的内置决策仍留在
`engine/decisions.py` 里，作为兼容路径保留；新世界不需要它。
迁移计划见 README 路线图。

## 7. 校验

```powershell
python tools\check_world_pack.py            # 校验全部世界包
python tools\check_world_pack.py tang_755   # 只校验一个
```

校验内容：

1. 目录存在、文件名正确；
2. JSON 能解析；
3. 必填字段齐全、类型正确；
4. 权重之和为 1、label 不重复、grades 门槛递减；
5. 引用的地区 / 派系 / 人物 key 在数据库中真实存在；
6. `world.json` 与 `rubric.json` 的 `horizon_months` 一致；
7. `decisions.json` 的条件名、效果名都在词表内；
8. `content.json` 的 faction / character / region 引用都存在。

任何一条不过，退出码非 0，CI 会拦下。

---

## 8. 给作者的最短路径

1. 复制 `backend/app/seed/packs/_template/` 改名为你的 `<world_key>`；
2. 写 `world.json`：定标题、时段、角色、期限；
3. 准备内容（v1 写在 seed 模块里；v2 将全部放进包）；
4. 写 `rubric.json`：想清楚"这段历史的成败看哪几件事"，给它们分配权重；
5. 跑 `python tools\check_world_pack.py <world_key>`；
6. 启动服务，看结局评分是否符合你的历史判断。
